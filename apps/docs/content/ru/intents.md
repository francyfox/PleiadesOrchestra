# Намерения

**Намерение** (intent) — это то, что, по мнению оркестратора, хочет сделать сообщение: искать, что-то добавить, открыть страницу, оплатить или просто поболтать. Планировщик превращает намерение в цель и выбирает инструменты, которые могут её достичь.

## Текущее поведение

Сейчас используется одна фиксированная таксономия, написанная для интернет-магазина (`packages/core/src/goap/intent-taxonomy.ts`). Это слой предметной области (магазина) в планировщике; всё остальное (имена инструментов, схемы, описания) берётся с сайта.

| Намерение | Значение |
| --- | --- |
| `chat` | Светская беседа; инструмент не нужен. |
| `chooseStore` | Перейти в конкретный магазин или переключиться на него. |
| `navigate` | Открыть страницу сайта. |
| `search` | Искать товары или спросить, что есть в наличии. |
| `filter` | Сузить результаты. |
| `select` | Открыть или выбрать один товар из результатов. |
| `addToCart` | Купить что-то или положить в корзину. |
| `removeFromCart` | Убрать что-то. |
| `checkout` | Оплатить и оформить заказ. |
| `paginate` | Больше результатов, следующая страница. |
| `compare` | Сравнить товары. |
| `other` | Всё остальное. |

(`readState` тоже существует, но только как роль *инструмента*: инструмента, который читает то, что хранит сайт, например корзину или бронирования. Сообщение никогда не классифицируется как `readState`.)

У каждого намерения есть фиксированные эффекты и предусловия (например, для `addToCart` нужны открытый магазин, выполненный поиск и разобранный запрос). Планировщик выстраивает цепочки инструментов через них. Инструменту назначается намерение по его имени (см. [Инструменты](/docs/tools/#How-the-orchestrator-reads-a-tool)).

### Как классифицируется сообщение

В таком порядке, срабатывает первое совпадение:

1. **Слова.** Лексические правила определяют только `checkout` и `removeFromCart`. Они проверяются по исходному тексту и его английскому переводу, на английском и русском.
2. **Память сайта.** Для каждого канала — небольшой классификатор, обученный на примерах, которые одобрил администратор (или которые были одобрены автоматически при высокой уверенности). Он молчит при уверенности ниже 0.85 и никогда не используется для `checkout` и `removeFromCart`.
3. **Laya**, модель решений, на английском переводе сообщения. Её ответ для `checkout` и `removeFromCart` отбрасывается и трактуется как `chat`.
4. **Запасной вариант** — `chat`, если Laya упала или не вернула ничего допустимого (сначала слова проверяются ещё раз).

У `checkout` и `removeFromCart` есть побочные эффекты, которые нельзя отменить перепланированием, поэтому они определяются только по явным словам в сообщении. Одной догадки модели никогда не достаточно, чтобы оплатить заказ или очистить корзину.

Ответы Laya сохраняются по каналам как примеры. Каждый из них имеет статус `pending`, пока администратор не одобрит, не отклонит или не исправит его на странице **Intents** в админ-панели, либо пока его откалиброванная уверенность не достигнет `LAYA_AUTO_APPROVE_CONFIDENCE` (по умолчанию 0.85) и он не будет одобрен автоматически. Одобренный пример меняет то, что память канала ответит в следующий раз.

### Что это значит вне магазина

Таксономия подходит сайтам, где посетитель ищет, добавляет и платит. На других сайтах у некоторых действий нет подходящего намерения. Пример с размером пиццы: «сделай пиццу побольше» может быть прочитано как `addToCart`, а инструмент вроде `set_pizza_size`, который классифицируется как `other` и не имеет эффектов, не может стать целью плана. Это известное ограничение, которое устраняет запланированная ниже работа.

## Запланировано: наборы намерений для каждого канала

> **Запланировано, не реализовано.** Отслеживается в GitHub issue PO-41. Ничего из описанного ниже пока не работает.

Идея в том, что набор намерений принадлежит каналу, а не коду:

- **Встроенный набор «Online shop».** Текущая таксономия выше вместе с описаниями для Laya, эффектами, предусловиями, правилом «только по явным словам» для `checkout` и `removeFromCart` и текстами шагов. Только для чтения; копируйте и правьте, как профили агентов.
- **Канал без набора** (планируемое значение по умолчанию для новых каналов). Сообщение выбирает инструмент сайта напрямую: Laya выбирает по имени и описанию инструмента (плюс `chat`), а целью становится результат этого инструмента. Таксономии нет, поэтому это работает на любом сайте.
- **Существующие каналы** переводятся на набор «Online shop», поэтому их поведение не меняется.
- **Админ-панель.** Выбор набора в настройках канала; отдельный экран для набора.
