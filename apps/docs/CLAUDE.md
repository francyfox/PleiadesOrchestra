# apps/docs internals

See root `CLAUDE.md` for monorepo commands, workflow, code style and repo-wide lessons.

## Stack

SveltePress (`@sveltepress/vite` + `@sveltepress/theme-default`) on SvelteKit 3 / Svelte 5, `adapter-static` (`build/`, fully prerendered, `trailingSlash = "always"`). SvelteKit 3 has no `svelte.config.js`: its options go through `sveltepress({ svelteKitOptions })` in `vite.config.ts`. Imports of own code use `#lib/*.js` (package `imports`; `$lib` is removed in Kit 3). Everything is in `devDependencies`; versions come from the root `workspaces.catalog`.

Run: `bun --cwd apps/docs run dev` (port 3004, listens on `[::1]`, open `http://localhost:3004`) or `cd apps/docs && bun run build` (`bun --cwd apps/docs run build` fails in this Bun; `bun run --cwd apps/docs build` works). `bun test src vite` for the unit tests.

E2E: `apps/e2e` tests the playground (`tests/playground*.spec.ts`). `bun run test:e2e` at the root; `cd apps/e2e && bunx playwright test playground` for the mocked ones. Playwright's second `webServer` builds this site with test env (fake agent URL, test keys from `tests/playground-env.ts`) and serves `build/` on :4311, so it overwrites `apps/docs/build`. Real-stack scenarios: `REAL_STACK=1 bunx playwright test playground-real` against `bun --cwd apps/docs run dev` with real keys in `.env`.

## Where things live

- `/`, `/ru/`, `/kk/` — landing: `src/routes/+page.md`, `src/routes/ru/+page.md`, `src/routes/kk/+page.md` (frontmatter `layout: false` strips the docs chrome) render `src/lib/components/landing/landing-page.svelte`; `/playground/` likewise per locale folder. One folder per language is what SveltePress `locales` expects (a `[[locale]]` route was invisible to its language switch). Pages read their language from the URL (`localeFromPath`). Copy per language and page section in `src/lib/landing/locales/<locale>/<section>.json` (i18next-style JSON); `src/lib/landing/content.ts` imports them and types `ru`/`kk` as `en`'s shape, so a missing language, file or key is a type error (`landingContent(locale)`; `i18n.ts` has `LOCALES`, `Locale`, `localizeHref`, `localeFromPath`). No Intlayer: plain typed objects and per-locale Markdown. Adding a language = `LOCALES`, a `locales/<locale>/` folder plus its imports in `content.ts`, header words in `CHROME` (`vite.config.ts`), a notice in `ReviewNotice.svelte`, `src/routes/<locale>/{,playground/}+page.md`, a `content/<locale>/` tree and the locale in `static/admin/config.yml`.
- Landing flow (`#flow`, `LandingFlow.svelte` + `LandingFlowNode.svelte` on xyflow) and its totals (`#results`, `LandingFlowResults.svelte`): measured numbers in `src/lib/landing/flow.data.ts` (from `bun efficiency` in `apps/benchmark`: per-step time and price of one run, aggregates of the whole run), pure logic in `flow.service.ts` (layout, nodes/edges, totals, formats, marketing figures; tested), runes in `flow.svelte.ts` (`useTabs`, `useFlowRun`, `useSvelteFlow`, `useFlowGraph`); components only call them. Texts per step id in `locales/<locale>/flow.json` and `results.json`. A headline figure shows only where the orchestrator wins (`claims`).
- Header: the theme's own language select (`locales` in `vite.config.ts`: per language its label, menu words and sidebar), keeps the current page on switch. The theme shows menu links and the select in the header only from 1440px; `src/lib/site-header.css` (imported by the root layout) keeps them there from 950px. Footer (root `+layout.svelte`): link to `/admin/`.
- `/playground/` — `src/lib/components/playground/` (iframe demo, widget panel, tools list, graph). Demo list and key lookup: `src/lib/playground/demos.ts`. Demos are static, self-contained and same-origin in `static/playground-demos/` (third-party: keep its `LICENSE` and `README.md`). Their `shared/webmcp-polyfill.js` is built from `packages/webmcp-polyfill` by `bun run polyfill` (runs before `dev`/`build`, git-ignored), so the demos run the polyfill the widget ships.
- `/docs/**`, `/ru/docs/**`, `/kk/docs/**` — pages are written per language in `content/<locale>/**/*.md` (`content/en/index.md` = `/docs/`, `content/ru/index.md` = `/ru/docs/`). `vite/content-routes.ts` mirrors them into `src/routes/docs/**` (en) and `src/routes/<locale>/docs/**` (generated, git-ignored, synced when the plugin is created and re-synced while `vite dev` runs; syncing in `config()` is too late, SveltePress scans routes earlier). Sidebar per language is built from that language's page titles (`sidebarItems`): the theme's auto sidebar only serves the site-level options and kept English titles on translated pages.
- `/docs/benchmarks/**` — `content/en/benchmarks/`: links to the benchmark reports, `bun efficiency`'s `report.txt` copied by hand into `static/benchmarks/<date>-<setup>.txt`, and how to rerun them (the landing's `#results` links here), English only and not in the CMS, its own sidebar group. Like drafts it is in `isEnglishOnly` (`vite/content-routes.ts`), so the translation test skips it and a ru/kk page must not link to it with a `/docs/` link.
- `/docs/drafts/**` — `content/en/drafts/`: working notes (design, contracts, plans, audits, lessons learned), English only. Not translated, not in the CMS; the translation test skips them (`DRAFTS_DIR` in `vite/content-routes.ts`), so a ru/kk page must not link to them with a `/docs/` link (the rewrite would target a missing page). GitHub issues link here with an anchor.
- Docs entry and sidebar: the theme marks every sidebar link under the current route active (`isLinkActive` prefix match), so no page sits at a bare folder URL: `content/<locale>/intro.md` and `drafts/overview.md` open their folder, `/docs/` and `/docs/drafts/` are generated redirects (`folderRedirects`, `+page.ts` + empty `+page.svelte`), and they sort first (`byPageOrder`). The sidebar is groups (docs, English-only Benchmarks, folded English-only Drafts): top-level items would each render as a group. `docs-theme.css` tightens the link padding and styles the Pagefind search (`LocalSearch`) and the logo title (always shown).
- Brand and SEO: `static/logo.svg` (from the shalotts site) is the theme `logo` (title next to it), the landing hero mark and the favicon (`app.html`, plus `apple-touch-icon.png`). `src/lib/site.ts` holds `SITE` (title/description, also `siteConfig`), `SITE_URL` and `OG_IMAGE` (`static/og.jpg`, 1200×630, made with ImageMagick from the logo + Poppins). `Seo.svelte` (`svelte-meta-tags`) writes only OpenGraph + Twitter (the theme already writes `<title>`/description): the root layout for non-docs pages, each docs page through the generated header with its title and description (`pageDescription` = first paragraph when the frontmatter has none, also written into the route's frontmatter for the theme's meta). Generated Svelte in a page goes into the `<script>` block: the Markdown pass autolinks URLs and turns `...` into `…` in markup.
- Agent files (llmstxt.org; no SveltePress plugin exists, `vitepress-plugin-llms` is VitePress-only): the same sync writes into `static/` (git-ignored) `llms.txt` (`/ru/llms.txt`, `/kk/llms.txt` per locale: H1, summary, `## Docs`, drafts and other languages under `## Optional`), `llms-full.txt` (all English pages except drafts) and every page's clean Markdown at its URL + `index.html.md` (`cleanMarkdown`: no frontmatter, `<code>{'…'}</code>` back to backticks). Each page gets `<link rel="alternate" type="text/markdown">` + `rel="describedby"` (llms.txt) and `CopyPage.svelte` (copy Markdown = fetch of that file, copy text = the rendered `.content` innerText, link to the `.md`, "Open in ChatGPT/Claude" (icons: Lucide; the two brand logos are the Elysia docs' SVGs copied whole into `src/lib/components/brand-icons/`, MIT) with a prompt naming the page and its Markdown; absolute URLs are filled in the browser, the prerendered HTML has them without origin). The page's own `# …` is dropped from the route file because the theme prints the frontmatter `title` as H1 (the `.md` keeps it).
- Translations: same file names, same headings in the same order and count as `en` (the test enforces it). Write links as in English (`/docs/x/#Anchor`): the copy step rewrites `/docs/x/` to `/<locale>/docs/x/` and maps each anchor to the id of the heading at the same position in the translated target page (also same-page `#Anchor`); ids use the theme's rule (`[&#$?* :/]` -> `-`, case kept, `_` on duplicates; only plain text and inline code count). An unknown page or anchor throws. Frontmatter `review: pending` makes the copy step put `ReviewNotice.svelte` at the top of the page.
- Design: root `+layout.svelte` imports `@repo/ui/fonts.css` + `tokens.css` (`packages/ui`, the shared design system) and `src/lib/docs-theme.css`, which maps the SveltePress theme onto the tokens (heavier selectors on purpose: the theme uses scoped/Uno rules). `themeColor` in `vite.config.ts` hands Uno `var(--primary)` etc.; Uno drops the alpha of `bg-svp-primary/8`, so the active sidebar link is restyled in `docs-theme.css`. Meta `theme-color` needs literal hex (`#ffffff` / `#30281d` = `--background`).
- Landing/playground styles: `src/lib/pleiades-site.css` — Tailwind v4 without preflight, its own names for the `@repo/ui` tokens (`--bg`, `--accent`, …) and a small reset scoped to `.po-site`, so nothing leaks into the docs pages. CSS in it hides the theme's sidebar/TOC on those pages (the theme renders them before the page sets its flags, so prerendered HTML can carry the previous page's sidebar).

## Analytics and CMS

- Umami: script in `src/app.html` (stats.shalotts.site, website id in place), `data-domains="pleiades.shalotts.site"` so dev and e2e are not counted.
- Sveltia CMS at `/admin/` (`static/admin/index.html` + `config.yml`, pinned version): edits `content/<locale>/**` in `francyfox/PleiadesOrchestra` on GitHub, sign-in with a personal access token. One CMS = one repo: shalotts.site keeps its own `/admin`, the same token works for both. A new docs page needs an entry in `config.yml`. `/admin/` is a static page: the prerender ignores it (`handleHttpError`).

## Env (`apps/docs/.env.example`)

Public, inlined into the bundle by `vite.config.ts` (`__PUBLIC_ENV__`; `$env/static/public` fails on unset vars and `$env/dynamic/*` can't be read while prerendering): `PUBLIC_PLEIADES_AGENT_URL` (orchestrator origin), `PUBLIC_PLEIADES_KEY` (shared fallback publishable key), `PUBLIC_PLEIADES_KEY_<DEMO>` (own channel per demo: `BASKETFUL`, `PIZZA_MAKER`, `EXPLAINER`, `FLIGHT_SEARCH`, `TICKET_BOOKING`, `HOTEL_CHAIN`). A demo without its own key uses the shared one and the widget panel calls `el.resetSession()` when the demo changes. Publishable keys only (`pk_`).

## Gotchas

- Markdown is compiled as Svelte. Braces in prose start an expression: put them in inline code. SveltePress turns inline code into a template literal and escapes only `\` and backticks, so `${` inside inline code is interpolated and breaks the build: write it as `<code>{'${VAR}'}</code>`. Fenced blocks are safe. A fence language must be in `highlighter.languages` (`vite.config.ts`), or Shiki fails the build.

- Uno (theme) writes the utilities it finds in landing files too (`.flex-col`, `.items-end`, …) unlayered, so they beat Tailwind's layered ones: a breakpoint override of such a class (`flex-col lg:flex-row`) never applies. Lay out without it (e.g. `flex-wrap`).
- A Markdown link to a static file (`[x](/benchmarks/a.txt)`) gets a trailing slash (`a.txt/`, a 404): write it as `<a href="/benchmarks/a.txt" rel="external">x</a>` (`rel="external"`: otherwise SvelteKit routes the click and shows its 404).
- Prerender: 404s and missing `#id`s inside `/docs` are logged as `[docs]` warnings, not build failures (`handleHttpError`/`handleMissingId`). Read them after `build`.
- The theme's TOC store leaks the last docs page's anchors into prerendered landing/playground HTML; the missing-id warnings for those paths are ignored.
